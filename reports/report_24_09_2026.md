# Feature Request: Fitur Like / Favorite Produk (Backend)

**Kepada: Tim Backend**
**Dari: Tim Frontend**
**Perihal: Kebutuhan API dan Skema Database untuk Fitur Like/Love Produk**
**Waktu Request:** 2026-09-24

Halo Tim Backend,

Untuk mendukung pembaruan UI/UX di sisi Frontend pada komponen produk_card.dart, produk_terlaris_card.dart, dan layout_detail_product.dart, kami membutuhkan implementasi fitur "Like" (suka) pada produk layaknya fitur _like_ pada sosial media. 

Saat ini, desain Frontend sudah menyertakan _button_ "Love/Like" beserta tempat untuk menampilkan total jumlah _likes_ pada sebuah produk, namun infrastruktur database dan API di backend belum tersedia.

Berikut adalah spesifikasi detail kebutuhan dari sisi Frontend yang kami harapkan untuk segera direalisasikan:

## 1. Perilaku Fitur (Business Logic)
- **Akses Terbuka:** Semua user yang sudah terautentikasi (termasuk user yang merupakan pemilik dari produk tersebut) diperbolehkan untuk melakukan _like_ pada produk.
- **Sistem Toggle (Like/Unlike):** 
  - User hanya bisa melakukan _like_ maksimal 1 kali pada satu produk (unik berdasarkan id_user dan id_produk).
  - Jika user menekan tombol _like_ lagi (ketika statusnya sudah dilike), maka sistem akan membatalkan _like_ tersebut (_unlike_).

## 2. Kebutuhan Perubahan Database
Dibutuhkan sebuah tabel pivot/relasi baru (misalnya produk_likes) untuk melacak user mana yang menyukai produk mana. 
- Rekomendasi Struktur Tabel:
  - id (Primary Key)
  - id_user (Foreign Key mengarah ke tabel users)
  - id_produk (Foreign Key mengarah ke tabel produk)
  - created_at / updated_at (Timestamp)

## 3. Kebutuhan Perubahan Endpoint API (Response Payload)
Pada seluruh endpoint API yang menampilkan data produk (seperti API pencarian, list produk, dan detail produk), kami meminta adanya **2 (dua) penambahan field (key) baru** di JSON response:

1. 	otal_likes (Integer): Mengembalikan jumlah/total keseluruhan user yang melakukan _like_ pada produk tersebut. 
2. is_liked (Boolean): Mengembalikan 	rue apabila _user yang sedang login_ sudah me-like produk tersebut, dan alse jika belum (atau jika sedang diakses sebagai _guest_ tanpa token). **Field ini sangat penting di sisi Frontend untuk menentukan apakah _button_ _like_ akan dirender dengan warna merah (menyala) atau abu-abu.**

**Contoh Ekspektasi JSON Response API Produk:**
`json
{
  "id_produk": 1,
  "nama_produk": "Tenda Eiger",
  "harga_sewa": 50000,
  // ... field lainnya ...
  
  "total_likes": 142,   // DITAMBAHKAN
  "is_liked": true      // DITAMBAHKAN
}
`

## 4. Kebutuhan Endpoint API Baru (Action)
Kami membutuhkan endpoint baru untuk mengeksekusi aksi _like_/_unlike_ dari sisi Frontend.

- **Endpoint:** POST /api/produk/{id_produk}/toggle-like
- **Headers:** Authorization: Bearer {token}
- **Response Sukses:** Harus dapat menginformasikan status terbaru, contoh:
`json
{
  "success": true,
  "message": "Berhasil melakukan like produk",
  "data": {
    "is_liked": true,
    "total_likes": 143
  }
}
`

Terima kasih atas bantuan dan kerjasamanya. Mohon beritahu kami jika endpoint tersebut sudah masuk tahap _staging_ atau _production_ agar tim Frontend dapat segera mengimplementasikannya pada komponen UI kami.

# Report: Perbaikan Backend (Mass Assignment Error pada ProdukLike)
**Tanggal:** 24 September 2026
**Kepada:** Tim Backend
**Dari:** Tim Frontend / App

Halo Tim Backend,

Terima kasih atas implementasi fitur Like produknya. Saat ini, *Frontend* (Mobile App) sudah sepenuhnya berhasil mengintegrasikan dan menembak endpoint /api/produk/{id_produk}/toggle-like.

Namun, saat tombol *Like* ditekan dari aplikasi, *endpoint* merespons dengan HTTP Status **500 Internal Server Error**. 
Setelah kami lacak dan ekstrak _exception_-nya, Laravel mengeluarkan error berikut:

\\\json
{
  "message": "Add [id_produk] to fillable property to allow mass assignment on [App\\Models\\ProdukLike].",
  "exception": "Illuminate\\Database\\Eloquent\\MassAssignmentException"
}
\\\

### Penyebab Masalah
Hal ini terjadi karena framework Laravel memblokir proses *Insert* (Mass Assignment) karena kolom id_produk (dan kemungkinan id_user) belum didaftarkan sebagai properti yang diizinkan untuk diisi secara dinamis (*fillable*) pada model Eloquent ProdukLike.

### Tindakan yang Diperlukan (Solusi)
Mohon tambahkan properti $fillable (atau $guarded) pada file Model App\Models\ProdukLike.php. 

**Contoh Perbaikan di Model ProdukLike.php:**
\\\php
namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class ProdukLike extends Model
{
    // Tambahkan baris ini agar fungsi create() atau insert() tidak di-block
    protected $fillable = [
        'id_user', 
        'id_produk'
    ];
    
    // ... relasi dan kode lainnya ...
}
\\\

Atau alternatifnya, jika tim menggunakan $guarded:
\\\php
protected $guarded = [];
\\\

Setelah *update* ini diterapkan di sisi Backend, fungsionalitas tombol *Like* di *Frontend* akan otomatis berfungsi 100% tanpa perlu ada pengubahan *code* lagi di aplikasi Flutter.

Terima kasih atas kerja samanya!

**Kepada:** Tim Backend
**Dari:** Tim Frontend / App

Halo Tim Backend,

Kami sedang melakukan *testing* untuk mengunggah *Banner* dan Foto Profil Toko di halaman *Frontend* baru. Saat aplikasi menembak POST /api/user/input-store/{id_user} dengan hanya mengirimkan *file multipart* oto_toko atau anner_toko (tanpa field lain karena *user* hanya berniat mengganti foto), Laravel merespons dengan **500 Internal Server Error (Validation Failed)**.

Berikut adalah respons dari server:
\\\json
{
  "message": "Terjadi kesalahan saat update password.", 
  "error": "The name store field is required. (and 2 more errors)"
}
\\\

### Catatan & Permintaan Perbaikan:
1. **Aturan Validasi Terlalu Ketat (Required):**
   Saat ini, fitur di aplikasi memungkinkan *user* mengubah data toko secara parsial/terpisah (misal: ganti foto saja, atau ganti nama saja). 
   **Permintaan:** Mohon ubah *rules* validasi di sisi Laravel (khususnya untuk proses *update*) agar kolom seperti 
ame_store, latitude, longitude, dll bersifat 
ullable atau sometimes. Sehingga jika kami tidak mengirimkan field tersebut, data yang lama di *database* tidak terhapus/ter-validasi.
   
2. **Pesan Error Tidak Relevan:**
   Pesan utamanya berbunyi "Terjadi kesalahan saat update password." padahal *endpoint* ini digunakan untuk manajemen toko. Mohon disesuaikan agar pesannya lebih relevan (misal: "Gagal menyimpan data toko").

*Workaround sementara dari Frontend:* Kami tidak bisa mengirim nilai latitude dan longitude secara statis (seperti "0") saat *update* foto, karena itu akan merusak data koordinat alamat toko pengguna yang sudah tersimpan di database. Oleh karena itu, fitur ubah foto toko di aplikasi masih terhenti *(blocked)* hingga penyesuaian validasi ini diimplementasikan di *Backend*.

# Feature Request: API Endpoint Profil Toko Publik & List Produk Toko

**Tanggal:** 24 September 2026
**Kepada:** Tim Backend
**Dari:** Tim Frontend / App
**Perihal: Kebutuhan API untuk Menampilkan Halaman Profil Toko Publik**

Halo Tim Backend,

Untuk mendukung pengembangan fitur **Profil Toko Publik** (seperti halaman toko di e-commerce), di mana pengguna lain dapat melihat detail toko serta daftar produk yang dijual/disewakan oleh toko tersebut, kami membutuhkan 2 (dua) endpoint API baru.

Saat ini, API yang tersedia hanya untuk mengambil data profil *user* yang sedang *login* (berdasarkan token) dan mengambil produk milik *user* tersebut. Kami membutuhkan endpoint yang bersifat *public* atau setidaknya bisa diakses untuk melihat data pengguna/toko lain berdasarkan `id_user`.

Berikut adalah spesifikasi detail kebutuhan API dari sisi Frontend:

## 1. Endpoint Detail Profil Toko Publik
Endpoint ini bertugas mengembalikan informasi publik mengenai sebuah toko (seperti banner, foto, statistik transaksi, dll).

- **Method:** `GET`
- **Endpoint:** `/api/store/{id_user}`
- **Headers:** `Authorization: Bearer {token}` (Optional/Required tergantung kebijakan, namun harus bisa melihat toko orang lain)
- **Response Sukses yang Diharapkan:**
```json
{
  "success": true,
  "data": {
    "id_user": 2,
    "nama_store": "Tenda Adventure Abadi",
    "deskripsi_toko": "Penyewaan alat camping terlengkap di Bandung",
    "foto_toko": "https://domain.com/assets/image/customers/logo_toko/tenda_abadi.png",
    "banner_toko": "https://domain.com/assets/image/customers/banner/banner.jpg",
    "rating_toko": 4.8,
    "total_ulasan": 120,
    "total_produk_aktif": 45,
    "total_transaksi_selesai": 350,
    "alamat": {
      "provinsi": "Jawa Barat",
      "kota": "Bandung",
      "detail_alamat": "Jl. Setiabudi No. 12"
    },
    "tanggal_bergabung": "2025-01-10T00:00:00.000Z"
  }
}
```
*Catatan: Pastikan atribut statistik seperti `total_transaksi_selesai` dihitung dari history tabel transaksi yang berstatus sukses untuk toko ini.*

## 2. Endpoint List Produk Toko Publik (dengan Filter Kategori)
Endpoint ini bertugas mengembalikan daftar produk milik toko tertentu, dilengkapi dengan dukungan filter/pencarian.

- **Method:** `GET`
- **Endpoint:** `/api/store/{id_user}/products`
- **Query Params:** 
  - `kategori` (String, Optional) - Untuk memfilter produk toko berdasarkan nama/ID kategori
  - `search` (String, Optional) - Pencarian nama produk dalam toko tersebut
- **Response Sukses yang Diharapkan:**
```json
{
  "success": true,
  "data": [
    {
      "id_produk": 15,
      "nama_produk": "Tenda Eiger 4 Orang",
      "harga_sewa": 50000,
      "kategori": "Tenda",
      "foto_depan": "https://...",
      "rating": 4.5,
      "total_disewa": 12
      // ... field produk lainnya yang standar ...
    }
    // ...
  ]
}
```

Sebagai informasi, saat ini tim Frontend akan menggunakan data *dummy* / *mocking* untuk menyusun UI/UX halamannya. Mohon kabari kami jika endpoint ini sudah tersedia di *Staging* atau *Production* agar kami dapat mengintegrasikannya.

Terima kasih atas bantuannya!
