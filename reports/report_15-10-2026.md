# Report Permintaan API Fitur Rekomendasi Wisata & Berita Terkini (Blog / Artikel)
**Tanggal**: 15-10-2026

## 1. Konteks Kendala & Latar Belakang
Pada halaman dashboard aplikasi mobile (`lib/layouts/layout_dashboard.dart`), saat ini terdapat dua section konten edukatif & informatif:
1. **Rekomendasi Wisata**: Menampilkan kartu-kartu tempat wisata alam / camping rekomendasi (berisi foto, nama wisata, lokasi, deskripsi singkat, dan link eksternal).
2. **Berita Terkini**: Menampilkan daftar berita terkini seputar dunia pendakian, camping, event alam, maupun tips outdoor (berisi thumbnail, judul berita, nama sumber, dan link eksternal).

**Kondisi Saat Ini:**
- Seluruh data untuk Rekomendasi Wisata dan Berita Terkini masih menggunakan data **dummy lokal** (`DummyProductApiResponse.getDataWisata()` dan `DummyProductApiResponse.getDataBerita()`).
- Ketika salah satu kartu wisata atau berita diklik oleh pengguna, aplikasi langsung membuka link eksternal melalui browser luar (`url_launcher`).

**Kebutuhan Baru (Upgrade ke Sistem Blog Dinamis dari Database Backend):**
1. **Dinamis dari Backend**: Seluruh data (foto, judul, deskripsi lengkap, lokasi wisata, pembuat/uploader artikel, tanggal & waktu upload, dan url sumber web) harus tersimpan di database backend dan disediakan melalui REST API.
2. **Halaman Detail Artikel (Ala Blog):** Saat kartu wisata atau berita diklik, pengguna **TIDAK langsung dilempar ke browser luar**, melainkan diarahkan terlebih dahulu ke **Halaman Detail Berita / Wisata** di dalam aplikasi mobile dengan format artikel blog yang interaktif dan nyaman dibaca.
3. **Pembeda Jelas antara Wisata & Berita:** Rekomendasi Wisata dan Berita Terkini harus memiliki pembedaan kategori/entitas yang jelas di database (misal: Wisata memiliki atribut lokasi & fokus destinasi camping, sedangkan Berita fokus pada kabar, event, dan tips outdoor).
4. **Halaman Khusus "Lihat Semua" (List Page Terpisah):**
   - Pada section *Rekomendasi Wisata*, tombol **"Lihat Semua"** akan mengarahkan pengguna ke halaman daftar lengkap rekomendasi wisata (`LayoutListWisata`).
   - Pada section *Berita Terkini*, tombol **"Lihat Semua"** akan mengarahkan pengguna ke halaman daftar lengkap berita terkini (`LayoutListBerita`).
5. **Fitur Filtering & Sorting (Terbaru, Terlama, dll):** Pada halaman daftar lengkap ("Lihat Semua"), pengguna membutuhkan filter pengurutan data (*Terbaru*, *Terlama*, *Terpopuler*, dll.) serta filter rentang waktu agar dapat mencari konten dengan mudah.

## 2. Kebutuhan Data & Informasi di Halaman Detail (Blog View)
Ketika pengguna membuka salah satu berita atau wisata, halaman detail di aplikasi mobile akan menyajikan:
1. **Foto Utama (Cover Image)**: Gambar banner beresolusi tajam yang di-host di storage backend.
2. **Judul Lengkap (Title)**: Judul berita atau nama destinasi wisata.
3. **Informasi Penulis / Pengunggah (Author / Uploader)**:
   - Nama pembuat/pengunggah berita/rekomendasi wisata (misal: Admin KampSewa atau nama kontributor).
   - Foto profil / avatar pembuat (jika ada).
4. **Tanggal & Waktu Upload (Timestamp Rilis)**:
   - **Tanggal upload:** Format tanggal lengkap (misal: "15 Oktober 2026").
   - **Waktu/Jam upload:** Format jam & menit (misal: "14:30 WIB").
   - **Waktu relatif:** Human-readable time ago (misal: "2 jam yang lalu", "Kemarin", "3 hari yang lalu").
   - **Timestamp standar:** ISO 8601 (`created_at`) untuk kemudahan formatting dinamis di frontend.
5. **Lokasi Destinasi** *(Khusus Rekomendasi Wisata)*: Contoh: "Batu, Jawa Timur" atau "Taman Nasional Gunung Gede Pangrango".
6. **Konten / Deskripsi Lengkap**: Teks deskripsi komprehensif atau isi artikel berita lengkap bergaya blog.
7. **Tautan Sumber Asli (Web URL Source)**: Tombol aksi eksternal bertuliskan *"Baca Selengkapnya di Sumber Asli"* atau *"Kunjungi Website Resmi Destinasi"* yang mengarahkan ke link website eksternal/portal aslinya.
8. **Statistik Pembaca (Views Count)**: Jumlah tayangan artikel untuk menandai popularitas berita/wisata.

## 3. Usulan Skema Database (Database Schema)

Tim backend dapat mengimplementasikan fitur ini menggunakan **satu tabel artikel terpadu dengan kolom tipe** (disarankan demi efisiensi) atau **dua tabel terpisah**. Berikut usulan tabel terpadu:

### Nama Tabel: `articles` (atau `berita_dan_wisata`)

| Nama Kolom | Tipe Data | Keterangan |
| :--- | :--- | :--- |
| `id` | `BIGINT UNSIGNED` (PK, Auto Increment) | ID unik berita/wisata |
| `tipe` | `ENUM('wisata', 'berita')` | Pembeda jenis konten (`wisata` atau `berita`) |
| `judul` | `VARCHAR(255)` | Judul artikel / nama tempat wisata |
| `slug` | `VARCHAR(255)` (Unique, Nullable) | URL-friendly slug (opsional untuk SEO web) |
| `gambar` | `VARCHAR(255)` | Path / nama file foto di storage backend |
| `deskripsi_singkat` | `VARCHAR(500)` / `TEXT` | Ringkasan teks untuk preview card di dashboard/list |
| `konten` | `LONGTEXT` | Isi lengkap artikel/deskripsi menyeluruh ala blog |
| `lokasi` | `VARCHAR(255)` (Nullable) | Khusus untuk tipe `wisata` (contoh: "Kab. Malang, Jawa Timur") |
| `sumber_url` | `VARCHAR(500)` (Nullable) | Link website rujukan / portal berita eksternal |
| `sumber_nama` | `VARCHAR(100)` (Nullable) | Label nama portal sumber (contoh: "Kompas Travel", "Detik Outdoor") |
| `author_id` | `BIGINT UNSIGNED` (FK ke `users.id`) | Relasi ke user/admin yang membuat/upload konten |
| `status` | `ENUM('published', 'draft', 'archived')` | Status publikasi (default `'published'`) |
| `views_count` | `INT UNSIGNED` (Default 0) | Jumlah pembaca artikel (untuk sorting terpopuler) |
| `created_at` | `TIMESTAMP` | Waktu dibuat / tanggal dan jam rilis |
| `updated_at` | `TIMESTAMP` | Waktu terakhir diubah |

## 4. Parameter Filtering & Sorting yang Diminta

Agar halaman "Lihat Semua" di mobile app memiliki filter yang lengkap dan interaktif, mohon sediakan query parameters berikut pada endpoint list:

| Parameter | Tipe Data | Nilai / Opsi yang Didukung | Keterangan |
| :--- | :--- | :--- | :--- |
| **`sort_by`** | `String` | • `terbaru` / `latest` *(Default)*<br>• `terlama` / `oldest`<br>• `terpopuler` / `popular`<br>• `a_z`<br>• `z_a` | • `terbaru`: Urut `created_at DESC`<br>• `terlama`: Urut `created_at ASC`<br>• `terpopuler`: Urut `views_count DESC`<br>• `a_z`: Urut abjad `judul ASC`<br>• `z_a`: Urut abjad `judul DESC` |
| **`filter_waktu`** | `String` | • `semua` *(Default)*<br>• `hari_ini`<br>• `minggu_ini`<br>• `bulan_ini`<br>• `tahun_ini` | Memfilter artikel berdasarkan rentang waktu upload |
| **`lokasi`** *(Khusus Wisata)* | `String` | Contoh: `Malang`, `Bogor`, `Jawa Timur` | Filter tempat wisata berdasarkan kota/daerah |
| **`search`** | `String` | Kata kunci bebas | Mencari kecocokan pada `judul`, `deskripsi_singkat`, atau `konten` |
| **`page`** | `Integer` | Default: `1` | Nomor halaman (Pagination) |
| **`per_page`** | `Integer` | Default: `10` | Jumlah data per halaman |
| **`limit`** | `Integer` | Contoh: `5` atau `6` | Membatasi jumlah data (khusus preview di dashboard) |

### C. Endpoint Pengelolaan Konten (Admin Web / CMS)
Untuk memudahkan admin memasukkan dan memperbarui berita maupun tempat wisata melalui web portal admin, mohon sediakan pula endpoint CRUD dengan otentikasi admin (`auth:sanctum`):
1. `POST /api/admin/wisata` (Form-data: `judul`, `gambar` file, `deskripsi_singkat`, `konten`, `lokasi`, `sumber_url`, `sumber_nama`)
2. `POST /api/admin/wisata/{id}` atau `PUT /api/admin/wisata/{id}` (Update data wisata)
3. `DELETE /api/admin/wisata/{id}` (Hapus data wisata)
4. `POST /api/admin/berita` (Form-data: `judul`, `gambar` file, `deskripsi_singkat`, `konten`, `sumber_url`, `sumber_nama`)
5. `POST /api/admin/berita/{id}` atau `PUT /api/admin/berita/{id}` (Update data berita)
6. `DELETE /api/admin/berita/{id}` (Hapus data berita)

## 6. Rencana Integrasi di Sisi Frontend Mobile (Aplikasi Flutter)
Setelah API di atas tersedia, tim frontend akan mengimplementasikan:
1. **Model & Service Baru:**
   - Membuat model Dart dinamis (`WisataModel` & `BeritaModel`) dengan parsing JSON lengkap termasuk atribut `konten`, `author`, `sumber_url`, `tanggal_upload`, `waktu_upload`, `waktu_lalu`, dan `views_count`.
   - Menambahkan service pemanggilan API dengan dukungan filter & sorting dinamis (`api_wisata.dart` dan `api_berita.dart`).
2. **Dashboard Integration:**
   - Section *Rekomendasi Wisata* dan *Berita Terkini* di [layout_dashboard.dart](file:///D:/Projects/Marketplace%20KampSewa/marketplace-kampsewa-app/lib/layouts/layout_dashboard.dart) akan menampilkan shimmer skeleton saat loading dan mengambil data real-time via API backend (limit 5-6 item).
3. **Halaman "Lihat Semua" (Dedicated List Screen) Lengkap dengan Filter:**
   - **`LayoutListWisata`**: Menampilkan seluruh rekomendasi wisata dalam bentuk grid / list card interaktif dengan tombol filter:
     - Filter Urutan: *Terbaru*, *Terlama*, *Terpopuler*, *A-Z*.
     - Filter Waktu: *Hari Ini*, *Minggu Ini*, *Bulan Ini*, *Semua*.
     - Filter Daerah/Lokasi & Search bar pencarian.
   - **`LayoutListBerita`**: Menampilkan feed artikel berita terkini dengan pagination, search bar, dan filter urutan (*Terbaru*, *Terlama*, *Terpopuler*).
4. **Halaman Detail Artikel (Blog Screen):**
   - **`LayoutDetailWisata`** dan **`LayoutDetailBerita`**:
     - Cover image dengan efek Hero animation / parallax.
     - Header judul besar, badge kategori/lokasi, dan info profil author pengunggah.
     - Badge waktu upload: tanggal rilis ("15 Oktober 2026"), jam rilis ("14:30 WIB"), dan waktu lampau ("2 jam yang lalu").
     - Tampilan body artikel berformat rapi dengan tipografi nyaman dibaca ala postingan blog.
     - Tombol eksternal floating/bottom CTA untuk membuka tautan sumber web asli (`sumber_url`).
     - Tombol bagikan (share).
